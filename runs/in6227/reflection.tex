\textbf{Human oversight.} I stayed in the loop mainly by \emph{designing the constraints} rather than by watching each step. Before any code existed I settled, in three question rounds with the agent, the decisions that define the skill: Variant~2; a hybrid design in which deterministic scripts compute every number and the LLM only decides and argues; exactly two contrasting models plus a prior baseline; CV-only model selection with a single use of the test set; AP and macro-F1 as primary metrics; and generalisation tests on two other datasets. I delegated both checkpoints (plan, report) to \emph{fresh} reviewer sub-agents that saw only the files, never the author's reasoning, and required every point and its resolution to be logged (\texttt{runs/in6227/oversight\_log.md}). Those reviews changed the run. The plan review added a missing ablation (zero handling for HGB) and showed that ablation deltas were measured against a selection-biased reference; the skill now reports the sd of paired fold differences and treats $|\Delta|<$ sd as ``no effect''. The report review caught a false sentence (``both models miss under a quarter of positives''; HGB misses 25.03\%) and two over-claims. I also changed the skill itself when it failed: the page check passed while a figure had silently floated to page~3, so it now compiles the main report separately and reads the page count from LaTeX.
\emph{What I would change.} Delegated review is not human review. Next time I would approve the plan myself at checkpoint~1, because that is where the judgement calls are (e.g.\ how to read the zero blocks). I would also freeze the plan and ablation list before the first full run: while the scripts were being debugged, one smoke run printed test metrics. This is disclosed in the log, and no decision traces to it, but a clean protocol would not allow it to happen.

\textbf{Critical evaluation.} The decision I find most questionable is treating the co-occurring zeros as missing (0$\to$NaN plus indicator). The skill argued that zeros shared by several continuous measures mark a structurally different group; that is plausible, but the evidence cuts both ways. (i) The ablations show no benefit for either model ($\Delta$ = [[R/ablations/0/delta|+4]] and [[R/ablations/1/delta|+4]], both within fold noise), so the transformation adds complexity for nothing measurable. (ii) The [[P/zero_blocks/0/rows|int]]-row block is 100\% negative. If those zeros are recorded \emph{after} the outcome, the indicator is a leakage channel; if they mean ``no activity'', it is a legitimate rule. With anonymised features the skill cannot tell the two apart, yet it turned an unresolved semantic question into a confident preprocessing step. I would have kept the raw zeros (simpler, equally accurate) and escalated the block to a human as a data question. A second questionable choice was keeping \texttt{composite\_rank} for HGB on the grounds that trees cannot form linear combinations. The ablation refuted this ($\Delta$ = [[R/ablations/4/delta|+4]]). I agree with how the report handled it: it states the refuted prediction instead of hiding it.

\textbf{Trustworthiness.} Three layers. (1) \emph{By construction}: prose numbers are tokens resolved from \texttt{results.json}, \texttt{profile.json} and \texttt{plan.json}; tables are generated from \texttt{results.json}; unresolved tokens abort the render; every literal typed in the prose is listed in \texttt{numbers\_audit.md}. (2) \emph{Independent review}: the reviewer agent re-derived the HGB tuned-threshold precision, recall, F1 and balanced accuracy, the LR CV AP mean$\pm$sd, the baseline macro-F1 and every ablation sd, and found no mismatch. (3) \emph{Manual check outside the pipeline}: with plain pandas on the raw CSV files I recomputed the labelled row counts ([[P/n_train|int]] / [[P/n_test|int]]), the positive share ([[P/minority_share|4]]) and the 265-row all-negative zero block. I confirmed that \texttt{composite\_rank} $- (0.006\,\texttt{aptitude\_score} + 0.004\,\texttt{performance\_score})$ never exceeds $5\times10^{-4}$ in absolute value, and that HGB's reported recall [[R/models/hgb/test/at_tuned/recall|4]] equals 2375/3168 from its confusion matrix. The one error found, the ``under a quarter'' sentence, was the only claim written as an inference in prose rather than as a token. That is the lesson: the token mechanism protects numbers, not the conclusions drawn from them, so conclusions still need a human or adversarial reader. Finally, generality was tested rather than asserted: the skill was run on two very different datasets (\texttt{examples/}: numeric binary without a test file; categorical 4-class). Those runs exposed two over-sensitive detectors (one flag per correlated pair; KS drift firing on a 114-row hold-out), which I fixed. All three reports were then regenerated with the same final code.
